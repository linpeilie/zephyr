发行版本
########

Zephyr 项目以源代码和针对不同目标架构和配置的构建脚本的形式提供，而不是作为二进制映像。Zephyr 项目的更新版本大约每六个月发布一次。

所有 Zephyr 项目源代码都维护在 `GitHub 仓库`_ 中。为了使用 Zephyr 项目的发布版本，建议您使用 :ref:`west` 来 :ref:`get_the_code` 您感兴趣的发布版本。

当前和过去发布版本的技术文档可在 https://docs.zephyrproject.org/ 获取（使用版本选择器选择您感兴趣的发布版本）。

.. _zephyr_release_cycle:

发布生命周期和维护
**********************************

主要版本和维护版本发布节奏
=====================================

Zephyr 项目使用六个月的节奏交付主要版本，大致在每年的四月和十月发布。

这一时间表有助于定期发布具有强大 QA 周期的版本，同时不会因太多新版本而让用户不堪重负。

这个节奏是可预测的，并避免了不同地区的许多主要节假日。

Zephyr 项目以不定期的方式交付维护版本，通常由与相关主要版本相关的足够重要的修复或增强功能的积累所驱动。

点版本表示主要发布分支中的一个点，在该点处完整的 QA 周期和发布流程验证新分支的内容。

长期支持和维护
=================================

虽然稳定版本在 2 个发布周期（大约 1 年）的持续时间内得到支持，但 Zephyr 项目将在更长的时间内支持某些特定版本，这些版本称为长期支持 (LTS) 版本。

Zephyr :ref:`长期支持 (LTS) <release_process_lts>` 版本大约每 2.5 到 3 年发布一次，并在发布后大约 5 年内从主树中独立分支和维护。

这为项目用户提供了更多的稳定性，并留出更多时间升级到下一个 LTS 版本。


过渡到新的发布节奏
========================================

向新发布节奏的过渡将于 2026 年开始。Zephyr 4.4 计划于 2026 年 4 月发布，后续版本将每六个月发布一次。

即将发布的版本的预计时间表如下:

+---------+-------------------+---------------------+
| 版本    | 计划日期          | 备注                |
+=========+===================+=====================+
| 4.4     | 2026年4月         |                     |
+---------+-------------------+---------------------+
| 4.5     | 2026年10月        |                     |
+---------+-------------------+---------------------+
| 4.6     | 2027年4月         | LTS4                |
+---------+-------------------+---------------------+
| 5.0     | 2027年10月        | 5.x 周期开始        |
+---------+-------------------+---------------------+
| 5.1     | 2028年4月         |                     |
+---------+-------------------+---------------------+
| 5.2     | 2028年10月        |                     |
+---------+-------------------+---------------------+
| 5.3     | 2029年4月         |                     |
+---------+-------------------+---------------------+
| 5.4     | 2029年10月        | LTS5                |
+---------+-------------------+---------------------+

从 5.x 发布周期开始，所有版本从一开始就将遵循新的六个月节奏。


安全修复
==============

Zephyr 中修复的每个安全问题都会回溯或提交到以下版本:

- 当前支持的长期支持 (LTS) 版本。

- 最近的两个版本。

更多信息，请参见 :ref:`安全漏洞报告 <reporting>`。

发布说明
*************

发布说明包含在版本的开发周期中对项目不同领域所做的更改列表。
需要用户修改其应用程序以支持新版本的更改可能会在发布说明中提及，但关于*需要*更改什么的详细信息将在版本的迁移指南中详细说明。

发布周期后对发布说明的更新是允许的，但仅限于样式、排版修复，以及从维护版本分支向上合并说明，其唯一目的是保持最新文档与项目中的更改一致。

迁移指南
****************

Zephyr 为所有主要版本提供迁移指南，以协助用户从以前的版本过渡。

如前一节所述，代码中需要用户采取操作（即修改源代码或配置文件）以保持其应用程序现有行为的更改属于迁移指南。这包括:

- 破坏性 API 更改
- 弃用
- 影响用户的设备树或 Kconfig 更改（默认值更改、重命名等）
- 产生影响的全树更改（例如，更改包含路径或默认使用不同的 C 标准库）
- 任何其他可能影响现有应用程序编译或运行时行为的内容

迁移指南中的每个条目都必须包含对更改的简要说明，并引用引入该更改的拉取请求，以便用户能够理解更改的上下文。
