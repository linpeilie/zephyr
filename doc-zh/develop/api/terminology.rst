.. _api_terms:

API 术语
###############

以下术语可用作简短的 API 标签,以指示允许的调用上下文(线程、ISR、内核前)、调用对当前线程状态的影响以及其他行为特征。

:ref:`api_term_reschedule`
   如果执行该函数到达重新调度点
:ref:`api_term_sleep`
   如果执行该函数会导致调用线程睡眠
:ref:`api_term_no-wait`
   如果函数的参数可以防止调用线程尝试睡眠
:ref:`api_term_isr-ok`
   如果该函数可以安全调用,并且无论从中断还是线程上下文调用都将具有其指定的效果
:ref:`api_term_pre-kernel-ok`
   如果该函数可以在内核完全初始化之前安全调用,并且从该上下文调用时将具有其指定的效果。
:ref:`api_term_async`
   如果函数可能在其初始化的操作完成之前返回(即函数返回和操作完成是异步的)
:ref:`api_term_supervisor`
   如果调用线程必须具有超级用户权限才能执行该函数

每个属性的行为影响的详细信息在以下部分中。

.. _api_term_reschedule:

reschedule (重新调度)
==========

reschedule 属性用于可以在其执行中到达 :ref:`重新调度点 <scheduling_v2>` 的函数。

详细信息
-------

此属性的重要性在于,当线程调用重新调度函数时,由于优先级更高的线程就绪,该线程可能会被暂停。暂停是否实际发生取决于与重新调度点相关的操作以及调用线程和就绪队列头的相对优先级。

请注意,在时间片或从中断执行的重新调度点的情况下,任何线程都可能在任何函数中被暂停。

非 **reschedule** 函数可以从线程或中断上下文调用。

**reschedule** 函数可以从线程上下文调用。

**reschedule** 但非 **sleep** 的函数可以从中断上下文调用。

.. _api_term_sleep:

sleep (睡眠)
=====

sleep 属性用于可以导致调用线程 :ref:`睡眠 <scheduling_v2>` 的函数。

说明
-----------

此属性在考虑仅使用非抢占式线程的应用程序时特别相关,因为内核不会在重新调度点替换正在运行的仅合作式线程,除非该线程明确调用了导致其睡眠的操作。

此属性并不意味着函数将无条件地睡眠,而是该操作可能需要调用线程在完成其操作之前暂停、等待或调用 :c:func:`k_yield`。此行为可能由 **no-wait** 调节。

**sleep** 函数隐式为 **reschedule**。

**sleep** 函数可以从线程上下文调用。

**sleep** 函数可以从中断和内核前上下文调用,当且仅当以 **no-wait** 模式调用时。

.. _api_term_no-wait:

no-wait (无等待)
=======

no-wait 属性用于也是 **sleep** 的函数,以表示函数的参数可以强制执行不会导致调用线程睡眠的执行路径。

说明
-----------

no-wait 函数的典型案例是接受超时的函数,可以向其传递 :c:macro:`K_NO_WAIT`。此特殊超时值的语义是,只要可以立即完成,就执行函数的操作,如果无法完成,则返回错误代码而不是睡眠。

正是使用 no-wait 功能才允许像 :c:func:`k_sem_take` 这样的函数从 ISR 调用,因为不允许在中断上下文中睡眠。

具有 no-wait 路径的函数并不意味着采用该路径可以保证函数是同步的。

具有此属性的函数只能在参数选择 no-wait 路径时从中断和内核前上下文调用。

.. _api_term_isr-ok:

isr-ok (ISR可用)
======

isr-ok 属性用于函数以表示无论从中断还是线程上下文调用它都能正常工作。

说明
-----------

任何非 **sleep** 的函数本质上都是 **isr-ok**。如果实现确保即使从中断上下文调用也能实现记录的行为,则 **sleep** 函数也是 **isr-ok**。这可以通过让实现检测调用上下文并将会睡眠的操作转移到线程来实现,或者通过记录当从非线程上下文调用时函数将返回特定错误(通常为 ``-EWOULDBLOCK``)来实现。

请注意,**no-wait** 函数仅在选择 no-wait 路径时才能从中断上下文安全调用。**isr-ok** 函数不需要提供 no-wait 路径。

.. _api_term_pre-kernel-ok:

pre-kernel-ok (内核前可用)
=============

pre-kernel-ok 属性用于函数以表示即使在内核主线程启动之前调用,它也能按记录工作。

说明
-----------

此属性在功能上类似于 **isr-ok**,但用于在 :c:macro:`DEVICE_DEFINE()` 或 :c:macro:`SYS_INIT()` 调用中调用的任何 API,这些调用可能以 ``PRE_KERNEL_1`` 或 ``PRE_KERNEL_2`` 初始化级别调用。

通常,**pre-kernel-ok** 函数在确定是否可以实现其所需行为时会检查 :c:func:`k_is_pre_kernel`。在许多情况下,它还会检查 :c:func:`k_is_in_isr`,以便也可以是 **isr-ok**。

.. _api_term_async:

async (异步)
=====

如果函数在其启动的操作完成之前可能返回,则该函数是 **async**(即异步)。异步函数通常会提供报告操作完成的机制,例如回调或事件。

非异步函数是同步的,即当函数返回时操作将始终完成。由于大多数函数都是同步的,因此此行为没有单独的属性来标识它。

说明
-----------

请注意,**async** 与上下文切换是正交的。某些 API 可能通过回调提供完成信息,但在等待启动操作所需的资源时可能会暂停;例如 :c:func:`spi_transceive_signal`。

如果函数既是 **no-wait** 又是 **async**,则选择 no-wait 路径仅保证函数不会睡眠。它不会影响操作是否会在函数返回之前完成。

.. _api_term_supervisor:

supervisor (超级用户)
==========

supervisor 属性仅在用户模式应用程序中相关,并指示该函数无法从用户模式调用。
