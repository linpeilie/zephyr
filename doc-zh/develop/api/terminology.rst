reschedule (重新调度)

重新调度（reschedule）==========

=====================

reschedule 属性用于可以在其执行中到达 :ref:`重新调度点 <scheduling_v2>` 的函数。

重新调度属性用于在执行过程中可能达到 :ref:`重新调度点 <scheduling_v2>` 的函数。

详细信息

详情-------

----

此属性的重要性在于,当线程调用重新调度函数时,由于优先级更高的线程就绪,该线程可能会被暂停。暂停是否实际发生取决于与重新调度点相关的操作以及调用线程和就绪队列头的相对优先级。

此属性的意义在于，当线程调用重新调度函数时，该线程可能因为更高优先级线程被就绪而被挂起。

是否真的发生挂起取决于与重新调度点相关联的操作以及调用线程和就绪队列头部之间的相对优先级。请注意,在时间片或从中断执行的重新调度点的情况下,任何线程都可能在任何函数中被暂停。



请注意，在时间片或从中断执行的重新调度点的情况下，任何线程都可能在任何函数中被挂起。非 **reschedule** 函数可以从线程或中断上下文调用。



不是 **重新调度** 的函数可以从线程或中断上下文调用。**reschedule** 函数可以从线程上下文调用。



**重新调度** 的函数可以从线程上下文调用。**reschedule** 但非 **sleep** 的函数可以从中断上下文调用。



是 **重新调度** 但不是 **睡眠** 的函数可以从中断上下文调用。.. _api_term_sleep:

无等待（no-wait）

=================说明

-----------

无等待属性用于也是 **睡眠** 的函数，以指示函数的参数可以强制执行不会导致

调用线程休眠的执行路径。no-wait 函数的典型案例是接受超时的函数,可以向其传递 :c:macro:`K_NO_WAIT`。此特殊超时值的语义是,只要可以立即完成,就执行函数的操作,如果无法完成,则返回错误代码而不是睡眠。



说明正是使用 no-wait 功能才允许像 :c:func:`k_sem_take` 这样的函数从 ISR 调用,因为不允许在中断上下文中睡眠。

----

具有 no-wait 路径的函数并不意味着采用该路径可以保证函数是同步的。

无等待函数的典型情况是接受超时的函数，

可以向其传递 :c:macro:`K_NO_WAIT`。此特殊超时值的语义是执行函数的操作，具有此属性的函数只能在参数选择 no-wait 路径时从中断和内核前上下文调用。

只要它可以立即完成，并在无法完成时返回错误代码而不是休眠。

======

具有无等待路径的函数并不意味着采用该路径保证函数是同步的。

isr-ok 属性用于函数以表示无论从中断还是线程上下文调用它都能正常工作。

具有此属性的函数仅当参数选择无等待路径时才可以从中断和内核前上下文调用。

说明

.. _api_term_isr-ok:-----------



ISR-OK任何非 **sleep** 的函数本质上都是 **isr-ok**。如果实现确保即使从中断上下文调用也能实现记录的行为,则 **sleep** 函数也是 **isr-ok**。这可以通过让实现检测调用上下文并将会睡眠的操作转移到线程来实现,或者通过记录当从非线程上下文调用时函数将返回特定错误(通常为 ``-EWOULDBLOCK``)来实现。

======

请注意,**no-wait** 函数仅在选择 no-wait 路径时才能从中断上下文安全调用。**isr-ok** 函数不需要提供 no-wait 路径。

isr-ok 属性用于函数，以指示无论是从中断还是线程上下文调用，它都有效。

==========================

async (异步)

pre-kernel-ok 属性用于函数，以指示即使在内核主线程启动之前调用时，=====

它也能按文档工作。

如果函数在其启动的操作完成之前可能返回,则该函数是 **async**(即异步)。异步函数通常会提供报告操作完成的机制,例如回调或事件。

说明

----非异步函数是同步的,即当函数返回时操作将始终完成。由于大多数函数都是同步的,因此此行为没有单独的属性来标识它。



此属性在函数中类似于 **isr-ok**，但用于任何预期在 :c:macro:`DEVICE_DEFINE()`说明

或 :c:macro:`SYS_INIT()` 调用中调用的 API，这些调用可能以-----------

``PRE_KERNEL_1`` 或 ``PRE_KERNEL_2`` 初始化级别调用。

请注意,**async** 与上下文切换是正交的。某些 API 可能通过回调提供完成信息,但在等待启动操作所需的资源时可能会暂停;例如 :c:func:`spi_transceive_signal`。

通常是 **内核前 OK** 的函数在确定是否能满足其所需行为时检查 :c:func:`k_is_pre_kernel`。

在许多情况下，它还会检查 :c:func:`k_is_in_isr`，以便它也可以是 **isr-ok**。如果函数既是 **no-wait** 又是 **async**,则选择 no-wait 路径仅保证函数不会睡眠。它不会影响操作是否会在函数返回之前完成。

异步（async）supervisor (超级用户)

=======================



如果函数可能在其初始化的操作完成之前返回，则该函数是 **异步** 的。supervisor 属性仅在用户模式应用程序中相关,并指示该函数无法从用户模式调用。

异步函数通常会提供一种机制，通过该机制报告操作完成，例如回调或事件。

不是异步的函数是同步的，即操作在函数返回时总是完成的。由于大多数函数
都是同步的，此行为没有不同的属性来标识它。

说明
----

请注意 **异步** 与上下文切换正交。某些 API 可能通过回调提供完成信息，
但在等待资源以启动操作时可能暂停；一个例子是 :c:func:`spi_transceive_signal`。

如果函数既是 **无等待** 又是 **异步**，则选择无等待路径只保证函数不会休眠。
它不影响操作是否在函数返回之前完成。
