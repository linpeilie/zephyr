内存堆
######

Zephyr 提供了一组实用程序,允许线程动态分配内存。

同步堆分配器
************

创建堆
======

定义堆的最简单方法是静态地使用 :c:macro:`K_HEAP_DEFINE` 宏。这将创建一个
具有给定名称的静态 :c:struct:`k_heap` 变量,用于管理指定大小的内存区域。

堆也可以创建用于管理使用 :c:func:`k_heap_init` 的应用程序控制的内存的
任意区域。

分配内存
========

可以使用 :c:func:`k_heap_alloc` 从堆分配内存,向其传递堆对象的地址和所需的
字节数。此函数的功能类似于标准 C ``malloc()``,在分配失败时返回 NULL 指针。

堆支持阻塞操作,允许线程休眠,直到内存可用。最后一个参数是 :c:type:`k_timeout_t`
超时值,指示线程在返回之前可以休眠多长时间,或者是常量超时值之一
:c:macro:`K_NO_WAIT` 或 :c:macro:`K_FOREVER`。

释放内存
========

使用 :c:func:`k_heap_alloc` 分配的内存必须使用 :c:func:`k_heap_free` 释放。
与标准 C ``free()`` 类似,提供的指针必须是 ``NULL`` 值或先前由
:c:func:`k_heap_alloc` 为同一堆返回的指针。释放 ``NULL`` 值定义为没有效果。

低级堆分配器
************

:c:struct:`k_heap` 抽象的底层实现由名为 :c:struct:`sys_heap` 的数据结构提供。
这实现了完全相同的分配语义,但不提供内核同步工具。它可用于希望在同步不可用或
更复杂的上下文(例如用户空间)中管理自己的内存块的应用程序。与 ``k_heap``
不同,对单个堆的任何 ``sys_heap`` 函数的所有调用都必须由调用者序列化。禁止
从单独的线程同时使用。

实现
====

在内部,``sys_heap`` 内存块被划分为 8 字节的"块"。所有分配都是从连续的块
区域中进行的。每个分配或未使用块的第一个块都以块头为前缀,该块头存储块的长度、
物理内存中下一个较低("左")块的长度、指示块是否正在使用的位,以及块索引链接
指针,指向"空闲列表"中的前一个和下一个块,未使用的块被添加到该列表中。

堆代码采取合理的措施来避免碎片。空闲块列表按其大小存储在"桶"中,每个桶存储
一个 2 的幂内的块(即 3-4 块的桶,5-8、9-16 等的另一个桶...)这允许从可用的
最小/最碎片化块中进行新分配。此外,当分配被释放并添加到堆时,它们会自动与
相邻的空闲块组合以防止碎片。

所有元数据都存储在连续堆内存块的开头,包括桶列表头的可变长度列表(取决于堆
大小)。唯一需要的外部内存是 :c:struct:`sys_heap` 结构本身。

``sys_heap`` 函数是不同步的。任何用户都必须注意防止并发访问。一次只能有一个
上下文位于 API 函数之一内。

堆代码注意呈现高性能和可靠延迟。所有 ``sys_heap`` API 函数都保证在恒定时间内
完成。在典型架构上,它们都将在 1-200 个周期内完成。一个复杂性是,为分配搜索
最小桶大小(可能适合的空闲块集)具有编译时迭代上限,以防止无限列表搜索,
代价是一些碎片抵抗力。此 :kconfig:option:`CONFIG_SYS_HEAP_ALLOC_LOOPS` 值
可以由用户在构建时选择,默认值为 3。

多堆包装器实用程序
******************

``sys_heap`` 实用程序要求所有托管内存都在单个连续块中。复杂的微控制器应用程序
通常具有更复杂的内存设置,它们仍希望动态管理为"堆"。例如,内存可能作为单独的
不连续区域存在,不同区域可能具有不同的缓存、性能或功耗行为,外围设备可能只能
对某些区域执行 DMA 等...

对于这些情况,Zephyr 提供了 ``sys_multi_heap`` 实用程序。实际上,这是一个或
多个 ``sys_heap`` 对象集的简单包装器。它应该在其子堆之后通过
:c:func:`sys_multi_heap_init` 初始化,之后可以通过
:c:func:`sys_multi_heap_add_heap` 将每个堆添加到托管集。不提供销毁实用程序;
就像 ``sys_heap`` 一样,希望销毁多堆的应用程序应简单地确保所有分配的块都已
释放(或至少永远不会再次使用),并将底层内存重新用于另一种用途。

它有一对分配入口点,:c:func:`sys_multi_heap_alloc` 和
:c:func:`sys_multi_heap_aligned_alloc`。这些函数的行为与具有类似名称的
``sys_heap`` 函数相同,只是它们还接受不透明的"配置"参数。此指针不被多堆代码
本身检查;相反,它被传递给初始化时提供的回调函数。此应用程序提供的回调负责从
托管堆之一执行底层分配,并可以以任何喜欢的方式使用配置参数来做出该决定。

要修改已分配缓冲区的大小(无论是缩小还是扩大),您可以使用
:c:func:`sys_multi_heap_realloc` 和 :c:func:`sys_multi_heap_aligned_realloc`
API。如果缓冲区无法在当前所在的堆上扩大,则可以使用配置参数指定的任何符合
条件的堆。

不使用时,可以通过 :c:func:`sys_multi_heap_free` 释放多堆。应用程序不需要
传递配置参数。从任何托管 ``sys_heap`` 对象分配的内存都可以以相同的方式释放。

系统堆
******

:dfn:`系统堆` 是一个预定义的内存分配器,允许线程以类似 :c:func:`malloc` 的
方式从公共内存区域动态分配内存。

仅定义单个系统堆。与其他堆或内存池不同,系统堆不能使用其内存地址直接引用。

系统堆的大小可配置为任意大小,取决于空间可用性。

线程可以通过调用 :c:func:`k_malloc` 动态分配堆内存块。分配块的地址保证在
指针大小的倍数上对齐。如果找不到合适的堆内存块,则返回 ``NULL``。

当线程完成堆内存块后,它可以通过调用 :c:func:`k_free` 将块释放回系统堆。

定义堆内存池
============

堆内存池的大小使用 :kconfig:option:`CONFIG_HEAP_MEM_POOL_SIZE` 配置选项
指定。

默认情况下,堆内存池大小为零字节。此值指示内核不定义堆内存池对象。最大大小
受系统中可用内存量的限制。如果指定的大小无法支持,项目构建将在链接阶段失败。

此外,每个子系统(板、驱动程序、库等)可以通过定义带有前缀
``HEAP_MEM_POOL_ADD_SIZE_`` 的 Kconfig 选项来设置自定义要求(此值以字节为单位)。
如果多个子系统指定自定义值,这些值的总和将用作最小要求。如果应用程序尝试设置
小于最小值的值,这将被忽略,而使用最小值。

要强制使用小于最小值的值,应用程序可以启用
:kconfig:option:`CONFIG_HEAP_MEM_POOL_IGNORE_MIN` 选项。当优化堆大小并且
可以更准确地确定特定应用程序的最小要求时,这可能很有用。

分配内存
========

通过调用 :c:func:`k_malloc` 分配堆内存块。

以下代码分配 200 字节的堆内存块,然后用零填充它。如果未获得合适的块,则发出
警告。

.. code-block:: c

    char *mem_ptr;

    mem_ptr = k_malloc(200);
    if (mem_ptr != NULL)) {
        memset(mem_ptr, 0, 200);
	...
    } else {
        printf("未分配内存");
    }

释放内存
========

通过调用 :c:func:`k_free` 释放堆内存块。

以下代码分配 75 字节的内存块,然后在不再需要时释放它。

.. code-block:: c

    char *mem_ptr;

    mem_ptr = k_malloc(75);
    ... /* 使用内存块 */
    k_free(mem_ptr);

建议用途
========

使用堆内存池以类似 :c:func:`malloc` 的方式动态分配内存。
