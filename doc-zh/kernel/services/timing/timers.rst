定时器
######

:dfn:`定时器` 是一个内核对象,它使用内核的系统时钟来测量时间的流逝。当定时器的
指定时间限制到达时,它可以执行应用程序定义的操作,或者它可以简单地记录到期并等待
应用程序读取其状态。

.. contents::
    :local:
    :depth: 2

概念
****

可以定义任意数量的定时器(仅受可用 RAM 限制)。每个定时器由其内存地址引用。

定时器具有以下关键属性:

* **持续时间**,指定定时器第一次到期前的时间间隔。这是一个 :c:type:`k_timeout_t`
  值,可以通过不同单位初始化。

* **周期**,指定第一次到期后所有定时器到期之间的时间间隔,也是 :c:type:`k_timeout_t`。
  它必须是非负的。周期为 ``K_NO_WAIT``(即零)或 ``K_FOREVER`` 意味着定时器是
  单次定时器,在单次到期后停止。(例如,如果定时器以 200 的持续时间和 75 的周期
  启动,它将在 200 毫秒后首次到期,然后每 75 毫秒到期一次。)

* 每次定时器到期时执行的**到期函数**。该函数由系统时钟中断处理程序执行。如果
  不需要到期函数,可以指定 ``NULL`` 函数。

* 如果定时器在运行时被提前停止,则执行的**停止函数**。该函数由停止定时器的线程
  执行。如果不需要停止函数,可以指定 ``NULL`` 函数。

* **状态**值,指示自上次读取状态值以来定时器到期的次数。

定时器在使用之前必须初始化。这指定其到期函数和停止函数值,将定时器的状态设置为零,
并将定时器置于**已停止**状态。

通过指定持续时间和周期来**启动**定时器。定时器的状态重置为零,然后定时器进入
**运行**状态并开始倒计时到期。

请注意,定时器的持续时间和周期参数指定将流逝的**最小**延迟。由于内部系统定时器
精度(以及潜在的运行时交互,如中断延迟),从相关系统时间 API 读取测量的时间可能
已经过去更多时间。但至少保证已经过去这么多时间。

当运行中的定时器到期时,其状态递增,定时器执行其到期函数(如果存在);如果线程
正在等待定时器,它将被解除阻塞。如果定时器的周期为零,定时器进入停止状态;
否则,定时器以等于其周期的新持续时间重新启动。

如果需要,可以在倒计时中途停止运行中的定时器。定时器的状态保持不变,然后定时器
进入停止状态并执行其停止函数(如果存在)。如果线程正在等待定时器,它将被解除
阻塞。尝试停止非运行定时器是允许的,但对定时器没有影响,因为它已经停止。

如果需要,可以在倒计时中途重新启动运行中的定时器。定时器的状态重置为零,然后
定时器开始使用调用者指定的新持续时间和周期值倒计时。如果线程正在等待定时器,
它继续等待。

可以随时直接读取定时器的状态,以确定自上次读取其状态以来定时器到期的次数。
读取定时器的状态会将其值重置为零。还可以读取定时器到期前的剩余时间;值为零
表示定时器已停止。

线程可以通过与定时器**同步**来间接读取定时器的状态。这会阻塞线程,直到定时器的
状态非零(表示它至少到期一次)或定时器停止;如果定时器状态已经非零或定时器已经
停止,线程将继续而不等待。同步操作返回定时器的状态并将其重置为零。

.. note::
    只有单个用户应检查任何给定定时器的状态,因为读取状态(直接或间接)会改变
    其值。同样,一次只有一个线程应与给定定时器同步。ISR 不允许与定时器同步,
    因为 ISR 不允许阻塞。

实现
****

定义定时器
==========

使用类型 :c:struct:`k_timer` 的变量定义定时器。然后必须通过调用
:c:func:`k_timer_init` 初始化它。

以下代码定义并初始化定时器。

.. code-block:: c

    struct k_timer my_timer;
    extern void my_expiry_function(struct k_timer *timer_id);

    k_timer_init(&my_timer, my_expiry_function, NULL);

或者,可以通过调用 :c:macro:`K_TIMER_DEFINE` 在编译时定义和初始化定时器。

以下代码与上面的代码段具有相同的效果。

.. code-block:: c

    K_TIMER_DEFINE(my_timer, my_expiry_function, NULL);

使用定时器到期函数
==================

以下代码使用定时器定期执行非平凡操作。由于所需的工作无法在中断级别完成,
定时器的到期函数将工作项提交到 :ref:`系统工作队列 <workqueues_v2>`,
其线程执行工作。

.. code-block:: c

    void my_work_handler(struct k_work *work)
    {
        /* 执行需要定期完成的处理 */
        ...
    }

    K_WORK_DEFINE(my_work, my_work_handler);

    void my_timer_handler(struct k_timer *dummy)
    {
        k_work_submit(&my_work);
    }

    K_TIMER_DEFINE(my_timer, my_timer_handler, NULL);

    ...

    /* 启动每秒到期一次的周期性定时器 */
    k_timer_start(&my_timer, K_SECONDS(1), K_SECONDS(1));

读取定时器状态
==============

以下代码直接读取定时器的状态以确定定时器是否已到期。

.. code-block:: c

    K_TIMER_DEFINE(my_status_timer, NULL, NULL);

    ...

    /* 启动在 200 毫秒后到期的单次定时器 */
    k_timer_start(&my_status_timer, K_MSEC(200), K_NO_WAIT);

    /* 执行工作 */
    ...

    /* 检查定时器状态 */
    if (k_timer_status_get(&my_status_timer) > 0) {
        /* 定时器已到期 */
    } else if (k_timer_remaining_get(&my_status_timer) == 0) {
        /* 定时器在到期前被停止(由其他人) */
    } else {
        /* 定时器仍在运行 */
    }

使用定时器状态同步
==================

以下代码执行定时器状态同步,以允许线程执行有用的工作,同时确保一对协议操作由
指定的时间间隔分隔。

.. code-block:: c

    K_TIMER_DEFINE(my_sync_timer, NULL, NULL);

    ...

    /* 执行第一个协议操作 */
    ...

    /* 启动在 500 毫秒后到期的单次定时器 */
    k_timer_start(&my_sync_timer, K_MSEC(500), K_NO_WAIT);

    /* 执行其他工作 */
    ...

    /* 确保定时器已到期(如有必要,等待到期) */
    k_timer_status_sync(&my_sync_timer);

    /* 执行第二个协议操作 */
    ...

.. note::
    如果线程没有其他工作要做,它可以简单地在两个协议操作之间休眠,而无需使用
    定时器。

建议用途
********

使用定时器在指定时间后启动异步操作。

使用定时器确定是否已经过指定的时间。特别是,当需要比简单的 :c:func:`k_sleep`
和 :c:func:`k_usleep` 调用提供的更高精度和/或单位控制时,应使用定时器。

使用定时器在执行涉及时间限制的操作时执行其他工作。

.. note::
   如果线程需要测量执行操作所需的时间,它可以直接读取
   :ref:`系统时钟或硬件时钟 <kernel_timing>`,而不是使用定时器。
