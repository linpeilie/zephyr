互斥锁
######

:dfn:`互斥锁` 是实现传统可重入互斥锁的内核对象。互斥锁通过确保对资源的互斥访问,
允许多个线程安全地共享关联的硬件或软件资源。

.. contents::
    :local:
    :depth: 2

概念
****

可以定义任意数量的互斥锁(仅受可用 RAM 限制)。每个互斥锁由其内存地址引用。

互斥锁具有以下关键属性:

* **锁定计数**,指示已锁定互斥锁的线程锁定它的次数。计数为零表示互斥锁已解锁。

* **拥有线程**,当互斥锁被锁定时,标识已锁定互斥锁的线程。

互斥锁在使用之前必须初始化。这会将其锁定计数设置为零。

需要使用共享资源的线程必须首先通过**锁定**关联的互斥锁来获得访问它的独占权限。
如果互斥锁已被另一个线程锁定,请求线程可以选择等待互斥锁解锁。

锁定互斥锁后,线程可以根据需要安全地使用关联资源;但是,尽可能短时间地持有锁被
认为是良好的做法,以避免对想要使用资源的其他线程产生负面影响。当线程不再需要资源时,
它必须**解锁**互斥锁以允许其他线程使用资源。

任意数量的线程可以同时等待锁定的互斥锁。当互斥锁解锁时,它会被等待时间最长的
最高优先级线程锁定。

.. note::
    互斥锁对象*不*设计供 ISR 使用。

可重入锁定
==========

允许线程锁定它已经锁定的互斥锁。这允许线程在其执行中的某个点访问关联资源,此时
互斥锁可能已经锁定,也可能尚未锁定。

线程重复锁定的互斥锁必须解锁相等次数,然后互斥锁才能完全解锁,以便可以被另一个
线程声明。

优先级继承
==========

已锁定互斥锁的线程有资格获得 :dfn:`优先级继承`。这意味着如果更高优先级的线程
开始等待互斥锁,内核将*临时*提升线程的优先级。这允许拥有线程通过以与等待线程
相同的优先级执行来更快地完成其工作并释放互斥锁。一旦互斥锁被解锁,解锁线程将
其优先级重置为锁定该互斥锁之前的级别。

.. note::
    :kconfig:option:`CONFIG_PRIORITY_CEILING` 配置选项限制内核由于优先级继承
    可以提升线程优先级的高度。默认值 0 允许无限提升。

拥有线程的基本优先级在获得锁时保存在互斥锁中。每次更高优先级的线程等待互斥锁时,
内核都会调整拥有线程的优先级。当拥有线程释放锁时(或者如果高优先级等待线程超时),
内核从互斥锁中保存的值恢复线程的基本优先级。

只要只涉及一个锁定的互斥锁,这对于优先级继承就能很好地工作。但是,如果涉及多个
互斥锁,如果互斥锁不是以与先前提升拥有线程优先级相反的顺序解锁的,则会观察到
次优行为。因此,建议当多个互斥锁在不同优先级的线程之间共享时,线程一次只锁定
一个互斥锁。

实现
****

定义互斥锁
==========

使用类型 :c:struct:`k_mutex` 的变量定义互斥锁。然后必须通过调用
:c:func:`k_mutex_init` 初始化它。

以下代码定义并初始化互斥锁。

.. code-block:: c

    struct k_mutex my_mutex;

    k_mutex_init(&my_mutex);

或者,可以通过调用 :c:macro:`K_MUTEX_DEFINE` 在编译时定义和初始化互斥锁。

以下代码与上面的代码段具有相同的效果。

.. code-block:: c

    K_MUTEX_DEFINE(my_mutex);

锁定互斥锁
==========

通过调用 :c:func:`k_mutex_lock` 锁定互斥锁。

以下代码基于上面的示例,如果互斥锁已被另一个线程锁定,则无限期等待互斥锁变为可用。

.. code-block:: c

    k_mutex_lock(&my_mutex, K_FOREVER);

以下代码等待最多 100 毫秒以使互斥锁变为可用,如果互斥锁未变为可用,则发出警告。

.. code-block:: c

    if (k_mutex_lock(&my_mutex, K_MSEC(100)) == 0) {
        /* 互斥锁成功锁定 */
    } else {
        printf("无法锁定 XYZ 显示器\n");
    }

解锁互斥锁
==========

通过调用 :c:func:`k_mutex_unlock` 解锁互斥锁。

以下代码基于上面的示例,解锁先前由线程锁定的互斥锁。

.. code-block:: c

    k_mutex_unlock(&my_mutex);

建议用途
********

使用互斥锁提供对资源(如物理设备)的独占访问。

配置选项
********

相关配置选项:

* :kconfig:option:`CONFIG_PRIORITY_CEILING`

Futex API 参考
**************

k_futex 是一个轻量级互斥原语,旨在最小化内核参与。无争用操作仅依赖于对共享内存的
原子访问。k_futex 被跟踪为内核对象,可以驻留在用户内存中,以便任何访问都绕过内核
对象权限管理机制。

.. doxygengroup:: futex_apis

用户模式互斥锁 API 参考
************************

sys_mutex 的行为几乎与 k_mutex 完全相同,额外的优势是 sys_mutex 实例可以驻留在
用户内存中。当未启用用户模式时,sys_mutex 的行为类似于 k_mutex。
