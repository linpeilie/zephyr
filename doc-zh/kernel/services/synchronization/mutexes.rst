互斥锁 (Mutexes)
################

:dfn:`互斥锁 (mutex)` 是一个内核对象，实现了传统的可重入互斥锁 (reentrant mutex)。互斥锁通过确保对资源的互斥访问 (mutually exclusive access)，允许多个线程安全地共享关联的硬件或软件资源。

.. contents::
    :local:
    :depth: 2

概念 (Concepts)
***************

可以定义任意数量的互斥锁（仅受可用 RAM 限制）。每个互斥锁通过其内存地址引用。

互斥锁具有以下关键属性：

* 一个 **锁定计数 (lock count)**，指示已锁定互斥锁的线程锁定它的次数。计数为零表示互斥锁未锁定。

* 一个 **拥有线程 (owning thread)**，当互斥锁被锁定时，标识已锁定互斥锁的线程。

互斥锁在使用之前必须初始化。这会将其锁定计数设置为零。

需要使用共享资源的线程必须首先通过 **锁定 (locking)** 关联的互斥锁来获得访问它的独占权限。如果互斥锁已被另一个线程锁定，请求线程可以选择等待互斥锁解锁。

锁定互斥锁后，线程可以根据需要安全地使用关联资源；但是，尽可能短时间地持有锁被认为是良好的做法，以避免对想要使用资源的其他线程产生负面影响。当线程不再需要资源时，它必须 **解锁 (unlock)** 互斥锁以允许其他线程使用资源。

任意数量的线程可以同时等待一个被锁定的互斥锁。当互斥锁解锁时，它会被等待时间最长的最高优先级线程锁定。

.. note::
    互斥锁对象 **不** 设计用于 ISR。

可重入锁定 (Reentrant Locking)
===============================

允许线程锁定它已经锁定的互斥锁。这允许线程在其执行中的某个点访问关联资源，而此时互斥锁可能已经被锁定或未被锁定。

被线程重复锁定的互斥锁必须被解锁相同的次数，然后互斥锁才能完全解锁，以便其他线程可以获取它。

优先级继承 (Priority Inheritance)
==================================

已锁定互斥锁的线程有资格进行 :dfn:`优先级继承 (priority inheritance)`。这意味着如果一个更高优先级的线程开始等待该互斥锁，内核将 *临时* 提升该线程的优先级。这允许拥有线程通过以与等待线程相同的优先级执行来更快地完成其工作并释放互斥锁。一旦互斥锁被解锁，解锁线程会将其优先级重置为锁定该互斥锁之前的级别。

.. note::
    :kconfig:option:`CONFIG_PRIORITY_CEILING` 配置选项限制内核由于优先级继承可以将线程优先级提高到多高。默认值 0 允许无限提升。

拥有线程的基本优先级在获取锁时保存在互斥锁中。每次更高优先级的线程等待互斥锁时，内核都会调整拥有线程的优先级。当拥有线程释放锁时（或者如果高优先级等待线程超时），内核会从互斥锁中保存的值恢复线程的基本优先级。

只要只涉及一个被锁定的互斥锁，这种方法对于优先级继承效果很好。但是，如果涉及多个互斥锁，如果互斥锁的解锁顺序与之前拥有线程优先级提升的顺序相反，则会观察到次优行为。因此，当多个互斥锁在不同优先级的线程之间共享时，建议线程一次只锁定一个互斥锁。

实现 (Implementation)
*********************

定义互斥锁 (Defining a Mutex)
==============================

互斥锁使用 :c:struct:`k_mutex` 类型的变量定义。然后必须通过调用 :c:func:`k_mutex_init` 进行初始化。

以下代码定义并初始化了一个互斥锁。

.. code-block:: c

    struct k_mutex my_mutex;

    k_mutex_init(&my_mutex);

或者，可以通过调用 :c:macro:`K_MUTEX_DEFINE` 在编译时定义并初始化互斥锁。

以下代码与上面的代码段具有相同的效果。

.. code-block:: c

    K_MUTEX_DEFINE(my_mutex);

锁定互斥锁 (Locking a Mutex)
=============================

通过调用 :c:func:`k_mutex_lock` 来锁定互斥锁。

以下代码基于上面的示例，如果互斥锁已被另一个线程锁定，则无限期地等待互斥锁变为可用。

.. code-block:: c

    k_mutex_lock(&my_mutex, K_FOREVER);

以下代码等待最多 100 毫秒以使互斥锁变为可用，如果互斥锁未变为可用，则发出警告。

.. code-block:: c

    if (k_mutex_lock(&my_mutex, K_MSEC(100)) == 0) {
        /* 互斥锁成功锁定 */
    } else {
        printf("Cannot lock XYZ display\n");
    }

解锁互斥锁 (Unlocking a Mutex)
===============================

通过调用 :c:func:`k_mutex_unlock` 来解锁互斥锁。

以下代码基于上面的示例，解锁先前由线程锁定的互斥锁。

.. code-block:: c

    k_mutex_unlock(&my_mutex);

建议用途 (Suggested Uses)
*************************

使用互斥锁提供对资源（例如物理设备）的独占访问。

配置选项 (Configuration Options)
********************************

相关配置选项：

* :kconfig:option:`CONFIG_PRIORITY_CEILING`

Futex API 参考 (Futex API Reference)
************************************

k_futex 是一种轻量级互斥原语 (mutual exclusion primitive)，旨在最小化内核参与。无竞争操作仅依赖于对共享内存的原子访问 (atomic access)。k_futex 被跟踪为内核对象，并且可以驻留在用户内存中，这样任何访问都会绕过内核对象权限管理机制。

.. doxygengroup:: futex_apis

用户模式互斥锁 API 参考 (User Mode Mutex API Reference)
********************************************************

sys_mutex 的行为几乎与 k_mutex 完全相同，增加的优势是 sys_mutex 实例可以驻留在用户内存中。当用户模式未启用时，sys_mutex 的行为类似于 k_mutex。
