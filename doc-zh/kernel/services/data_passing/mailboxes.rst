邮箱
####

:dfn:`邮箱` 是一个内核对象,它提供了超越消息队列对象功能的增强消息队列能力。
邮箱允许线程同步或异步发送和接收任意大小的消息。

.. contents::
    :local:
    :depth: 2

概念
****

可以定义任意数量的邮箱(仅受可用 RAM 限制)。每个邮箱由其内存地址引用。

邮箱具有以下关键属性:

* 已发送但尚未接收的消息的**发送队列**。

* 等待接收消息的线程的**接收队列**。

邮箱在使用之前必须初始化。这会将其两个队列都设置为空。

邮箱允许线程(而不是 ISR)交换消息。发送消息的线程称为**发送线程**,而接收
消息的线程称为**接收线程**。每条消息只能由一个线程接收(即不支持点对多点和
广播消息传递)。

使用邮箱交换的消息是非匿名处理的,允许参与交换的两个线程知道(甚至指定)
另一个线程的身份。

消息格式
========

**消息描述符**是一种数据结构,它指定消息数据的位置以及邮箱如何处理消息。
发送线程和接收线程在访问邮箱时都提供消息描述符。邮箱使用消息描述符在兼容的
发送和接收线程之间执行消息交换。邮箱还在交换期间更新某些消息描述符字段,
允许两个线程知道发生了什么。

邮箱消息包含零个或多个字节的**消息数据**。消息数据的大小和格式由应用程序定义,
并且可以在一条消息到另一条消息之间变化。

**消息缓冲区**是由发送或接收消息数据的线程提供的内存区域。数组或结构变量
通常可用于此目的。

既没有任何形式的消息数据的消息称为**空消息**。

.. note::
    其消息缓冲区存在但包含零字节实际数据的消息*不是*空消息。

消息生命周期
============

消息的生命周期很简单。当发送线程将消息提供给邮箱时,消息被创建。然后消息由
邮箱拥有,直到它被提供给接收线程。接收线程可以在从邮箱接收消息时检索消息数据,
或者它可以在第二次后续邮箱操作期间执行数据检索。只有在数据检索发生时,消息才
由邮箱删除。

线程兼容性
==========

发送线程可以指定要向其发送消息的线程的地址,或通过指定 :c:macro:`K_ANY`
发送给任何线程。同样,接收线程可以指定它希望从中接收消息的线程的地址,或者
它可以通过指定 :c:macro:`K_ANY` 从任何线程接收消息。只有当发送线程和接收
线程的要求都得到满足时,消息才会被交换;这样的线程被称为**兼容的**。

例如,如果线程 A 向线程 B(并且仅向线程 B)发送消息,如果线程 B 尝试从线程 A
接收消息或者线程 B 尝试从任何线程接收,它将被线程 B 接收。如果线程 B 尝试从
线程 C 接收消息,则不会发生交换。消息永远不会被线程 C 接收,即使它尝试从
线程 A(或从任何线程)接收消息。

消息流控制
==========

邮箱消息可以**同步**或**异步**交换。在同步交换中,发送线程会阻塞,直到消息
已由接收线程完全处理。在异步交换中,发送线程在消息被另一个线程接收之前不等待
即可继续;这允许发送线程在消息被提供给接收线程并完全处理*之前*执行其他工作
(例如收集将在下一条消息中使用的数据)。给定消息交换使用的技术由发送线程确定。

同步交换技术提供了隐式形式的流控制,防止发送线程生成消息的速度快于接收线程
消耗它们的速度。异步交换技术提供了显式形式的流控制,允许发送线程在发送后续
消息之前确定先前发送的消息是否仍然存在。

实现
****

定义邮箱
========

使用类型 :c:struct:`k_mbox` 的变量定义邮箱。然后必须通过调用
:c:func:`k_mbox_init` 初始化它。

以下代码定义并初始化空邮箱。

.. code-block:: c

    struct k_mbox my_mailbox;

    k_mbox_init(&my_mailbox);

或者,可以通过调用 :c:macro:`K_MBOX_DEFINE` 在编译时定义和初始化邮箱。

以下代码与上面的代码段具有相同的效果。

.. code-block:: c

    K_MBOX_DEFINE(my_mailbox);

消息描述符
==========

消息描述符是类型 :c:struct:`k_mbox_msg` 的结构。只应使用下面列出的字段;
任何其他字段仅供内部邮箱使用。

*info*
    由消息发送者和接收者交换的 32 位值,其含义由应用程序定义。此交换是双向的,
    允许发送者在任何消息交换期间向接收者传递值,并允许接收者在同步消息交换期间
    向发送者传递值。

*size*
    消息数据大小,以字节为单位。在发送空消息时或发送没有实际数据的消息缓冲区时
    将其设置为零。接收消息时,将其设置为所需的最大数据量,或者如果不需要消息数据,
    则设置为零。邮箱在接收消息后使用实际交换的数据字节数更新此字段。

*tx_data*
    指向发送线程的消息缓冲区的指针。发送空消息时将其设置为 ``NULL``。接收消息时
    将此字段保留未初始化状态。

*tx_target_thread*
    所需接收线程的地址。将其设置为 :c:macro:`K_ANY` 以允许任何线程接收消息。
    接收消息时将此字段保留未初始化状态。邮箱在接收消息后使用实际接收者的地址
    更新此字段。

*rx_source_thread*
    所需发送线程的地址。将其设置为 :c:macro:`K_ANY` 以接收任何线程发送的消息。
    发送消息时将此字段保留未初始化状态。当消息放入邮箱时,邮箱使用实际发送者的
    地址更新此字段。

发送消息
========

线程首先创建其消息数据(如果有)来发送消息。

接下来,发送线程创建一个消息描述符,用于描述要发送的消息,如前一节所述。

最后,发送线程调用邮箱发送 API 来启动消息交换。如果当前有兼容的接收线程正在
等待,消息会立即提供给它。否则,消息会添加到邮箱的发送队列。

发送队列上可以同时存在任意数量的消息。发送队列中的消息根据发送线程的优先级
排序。优先级相等的消息排序,以便最旧的消息可以首先被接收。

对于同步发送操作,当接收线程已接收消息并检索消息数据时,操作通常完成。如果在
发送线程指定的等待时间到达之前未接收到消息,则消息将从邮箱的发送队列中删除,
发送操作失败。当发送操作成功完成时,发送线程可以检查消息描述符以确定哪个线程
接收了消息、交换了多少数据以及接收线程提供的应用程序定义的 info 值。

.. note::
   同步发送操作可能会无限期阻塞发送线程,即使线程指定了最大等待时间也是如此。
   等待时间仅限制邮箱在消息被另一个线程接收之前等待多长时间。一旦接收到消息,
   接收线程检索消息数据并解除发送线程阻塞所需的时间*没有*限制。

对于异步发送操作,操作始终立即完成。这允许发送线程继续处理,无论消息是立即
提供给接收线程还是添加到发送队列。发送线程可以选择指定一个信号量,当消息被
邮箱删除时(例如,当消息已被接收线程接收并检索其数据时)邮箱会给予该信号量。
使用信号量允许发送线程轻松实现流控制机制,确保邮箱在任何时间点从发送线程
(或一组发送线程)持有的消息不超过应用程序指定的数量。

.. note::
   异步发送消息的线程无法确定哪个线程接收了消息、交换了多少数据或接收线程
   提供的应用程序定义的 info 值。

发送空消息
----------

此代码使用邮箱同步传递 4 字节随机值给任何想要它的消费者线程。消息"info"字段
足够大,可以携带正在交换的信息,因此不使用消息的数据部分。

.. code-block:: c

    void producer_thread(void)
    {
        struct k_mbox_msg send_msg;

        while (1) {

            /* 生成要发送的随机值 */
            uint32_t random_value = sys_rand32_get();

            /* 准备发送空消息 */
            send_msg.info = random_value;
            send_msg.size = 0;
            send_msg.tx_data = NULL;
            send_msg.tx_target_thread = K_ANY;

            /* 发送消息并等待消费者接收它 */
            k_mbox_put(&my_mailbox, &send_msg, K_FOREVER);
        }
    }

使用消息缓冲区发送数据
----------------------

此代码使用邮箱同步传递可变大小的请求从生产者线程到任何想要它的消费者线程。
消息"info"字段用于交换有关每个线程可以处理的最大消息缓冲区大小的信息。

.. code-block:: c

    void producer_thread(void)
    {
        char buffer[100];
        int buffer_bytes_used;

        struct k_mbox_msg send_msg;

        while (1) {

            /* 生成要发送的数据 */
            ...
            buffer_bytes_used = ... ;
            memcpy(buffer, source, buffer_bytes_used);

            /* 准备发送消息 */
            send_msg.info = buffer_bytes_used;
            send_msg.size = buffer_bytes_used;
            send_msg.tx_data = buffer;
            send_msg.tx_target_thread = K_ANY;

            /* 发送消息并等待消费者接收它 */
            k_mbox_put(&my_mailbox, &send_msg, K_FOREVER);

            /* info、size 和 tx_target_thread 字段已更新 */

            /* 验证消息数据是否已完全接收 */
            if (send_msg.size < buffer_bytes_used) {
                printf("传输期间丢失了一些消息数据!");
                printf("接收者只有 %d 字节的空间", send_msg.info);
            }
        }
    }

接收消息
========

线程首先创建一个消息描述符来接收消息,该描述符描述它想要接收的消息。然后它
调用邮箱接收 API 之一。邮箱搜索其发送队列并从找到的第一个兼容线程获取消息。
如果不存在兼容的线程,接收线程可以选择等待。如果在接收线程指定的等待时间到达
之前没有出现兼容的线程,则接收操作失败。一旦接收操作成功完成,接收线程可以
检查消息描述符以确定哪个线程发送了消息、交换了多少数据以及发送线程提供的
应用程序定义的 info 值。

任意数量的接收线程可以同时在邮箱的接收队列上等待。线程根据其优先级排序;
优先级相等的线程排序,以便首先开始等待的线程可以首先接收消息。

.. note::
    由于消息描述符指定的线程兼容性约束,接收线程并不总是以先进先出 (FIFO)
    顺序接收消息。例如,如果线程 A 等待仅从线程 X 接收消息,然后线程 B 等待
    从线程 Y 接收消息,则来自线程 Y 到任何线程的传入消息将被提供给线程 B,
    线程 A 将继续等待。

接收线程控制它从传入消息中检索的数据量以及数据的最终位置。线程可以选择获取
消息中的所有数据、仅获取数据的初始部分或完全不获取任何数据。同样,线程可以
选择将数据复制到它选择的消息缓冲区中。

以下部分概述了接收线程在检索消息数据时可以使用的各种方法。

接收时检索数据
--------------

线程检索消息数据的最直接方法是在接收消息时指定消息缓冲区。线程指示消息缓冲区
的位置(必须不是 ``NULL``)及其大小。

邮箱将消息数据复制到消息缓冲区,作为接收操作的一部分。如果消息缓冲区不够大,
无法包含消息的所有数据,则任何未复制的数据都将丢失。如果消息不够大,无法用
数据填充所有缓冲区,则消息缓冲区的未使用部分保持不变。在所有情况下,邮箱都会
更新接收线程的消息描述符以指示复制了多少数据字节(如果有)。

立即数据检索技术最适合已知消息的最大大小的小消息。

以下代码使用邮箱处理来自任何生产者线程的可变大小请求,使用立即数据检索技术。
消息"info"字段用于交换有关每个线程可以处理的最大消息缓冲区大小的信息。

.. code-block:: c

    void consumer_thread(void)
    {
        struct k_mbox_msg recv_msg;
        char buffer[100];

        int i;
        int total;

        while (1) {
            /* 准备接收消息 */
            recv_msg.info = 100;
            recv_msg.size = 100;
            recv_msg.rx_source_thread = K_ANY;

            /* 获取数据项,根据需要等待 */
            k_mbox_get(&my_mailbox, &recv_msg, buffer, K_FOREVER);

            /* info、size 和 rx_source_thread 字段已更新 */

            /* 验证消息数据是否已完全接收 */
            if (recv_msg.info != recv_msg.size) {
                printf("传输期间丢失了一些消息数据!");
                printf("发送者尝试发送 %d 字节", recv_msg.info);
            }

            /* 计算所有消息字节的总和(从 0 到 100 个字节) */
            total = 0;
            for (i = 0; i < recv_msg.size; i++) {
                total += buffer[i];
            }
        }
    }

稍后使用消息缓冲区检索数据
--------------------------

接收线程可以选择在接收消息时延迟消息数据检索,以便稍后将数据检索到消息缓冲区中。
线程通过指定消息缓冲区位置为 ``NULL`` 和大小指示它以后愿意检索的最大数据量来
执行此操作。

邮箱不会将任何消息数据作为接收操作的一部分复制。但是,邮箱仍会更新接收线程的
消息描述符以指示可供检索的数据字节数。

然后接收线程必须按如下方式响应:

* 如果消息描述符大小为零,则发送者的消息不包含数据或接收线程不想接收任何数据。
  接收线程不需要采取任何进一步的操作,因为邮箱已经完成了数据检索并删除了消息。

* 如果消息描述符大小非零并且接收线程仍想检索数据,则线程必须调用
  :c:func:`k_mbox_data_get` 并提供足够大的消息缓冲区来容纳数据。邮箱将数据
  复制到消息缓冲区并删除消息。

* 如果消息描述符大小非零并且接收线程*不*想检索数据,则线程必须调用
  :c:func:`k_mbox_data_get` 并指定消息缓冲区为 ``NULL``。邮箱删除消息而不
  复制数据。

后续数据检索技术适用于不希望立即检索消息数据的应用程序。例如,当内存限制使得
接收线程总是提供能够容纳最大可能传入消息的消息缓冲区不切实际时,可以使用它。

以下代码使用邮箱的延迟数据检索机制仅在消息满足某些条件时才从生产者线程获取
消息数据,从而消除不需要的数据复制。发送者提供的消息"info"字段用于对消息进行
分类。

.. code-block:: c

    void consumer_thread(void)
    {
        struct k_mbox_msg recv_msg;
        char buffer[10000];

        while (1) {
            /* 准备接收消息 */
            recv_msg.size = 10000;
            recv_msg.rx_source_thread = K_ANY;

            /* 获取消息,但不获取其数据 */
            k_mbox_get(&my_mailbox, &recv_msg, NULL, K_FOREVER);

            /* 仅获取某些类型消息的消息数据 */
            if (is_message_type_ok(recv_msg.info)) {
                /* 检索消息数据并删除消息 */
                k_mbox_data_get(&recv_msg, buffer);

                /* 处理"buffer"中的数据 */
                ...
            } else {
                /* 忽略消息数据并删除消息 */
                k_mbox_data_get(&recv_msg, NULL);
            }
        }
    }
