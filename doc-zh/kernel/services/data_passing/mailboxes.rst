邮箱
####

:dfn:`邮箱` (mailbox) 是一种内核对象 (kernel object)，提供了超越消息队列对象能力的增强消息队列功能。
邮箱允许线程同步或异步发送和接收任意大小的消息。

.. contents::
    :local:
    :depth: 2

概念
****

可以定义任意数量的邮箱（仅受可用 RAM 限制）。每个邮箱通过其内存地址进行引用。

邮箱具有以下关键属性：

* 一个**发送队列** (send queue)，包含已发送但尚未接收的消息。

* 一个**接收队列** (receive queue)，包含正在等待接收消息的线程。

邮箱在使用前必须进行初始化 (initialized)，这会将其两个队列都设置为空。

邮箱允许线程（但不允许 ISR）交换消息。发送消息的线程称为**发送线程** (sending thread)，
而接收消息的线程称为**接收线程** (receiving thread)。每条消息只能由一个线程接收
（即不支持点对多点和广播消息传递）。

使用邮箱交换的消息是非匿名处理的，允许参与交换的两个线程都知道（甚至指定）另一个线程的身份。

消息格式
========

**消息描述符** (message descriptor) 是一种数据结构，指定消息数据的位置，以及邮箱如何处理消息。
发送线程和接收线程在访问邮箱时都提供消息描述符。邮箱使用消息描述符在兼容的发送和接收线程之间
执行消息交换。邮箱还会在交换期间更新某些消息描述符字段，使两个线程都知道发生了什么。

邮箱消息包含零个或多个字节的**消息数据** (message data)。消息数据的大小和格式由应用程序定义，
并且可以从一条消息到另一条消息而变化。

**消息缓冲区** (message buffer) 是由发送或接收消息数据的线程提供的内存区域。
数组或结构变量通常可用于此目的。

既没有任何形式的消息数据的消息称为**空消息** (empty message)。

.. note::
    消息缓冲区存在但包含零字节实际数据的消息*不是*空消息。

消息生命周期
===========

消息的生命周期很简单。消息在由发送线程给到邮箱时创建。然后消息由邮箱拥有，直到它被给到接收线程。
接收线程可以在从邮箱接收消息时检索消息数据，或者它可以在第二次后续邮箱操作期间执行数据检索。
只有在数据检索发生时，消息才会被邮箱删除。

线程兼容性
=========

发送线程可以指定消息发送到的线程的地址，或者通过指定 :c:macro:`K_ANY` 将其发送到任何线程。
同样，接收线程可以指定它希望从中接收消息的线程的地址，或者通过指定 :c:macro:`K_ANY`
从任何线程接收消息。只有当发送线程和接收线程的要求都得到满足时，才会交换消息；
这样的线程被称为**兼容** (compatible)。

例如，如果线程 A 向线程 B（且仅向线程 B）发送消息，如果线程 B 尝试从线程 A 接收消息，
或者如果线程 B 尝试从任何线程接收消息，则线程 B 将接收该消息。如果线程 B 尝试从线程 C 接收消息，
则不会发生交换。该消息永远不能被线程 C 接收，即使它尝试从线程 A（或从任何线程）接收消息。

消息流控制
=========

邮箱消息可以**同步** (synchronously) 或**异步** (asynchronously) 交换。在同步交换中，
发送线程会阻塞，直到消息被接收线程完全处理。在异步交换中，发送线程在消息被另一个线程接收之前
不会等待；这允许发送线程在消息被给到接收线程并完全处理*之前*执行其他工作
（例如收集将在下一条消息中使用的数据）。给定消息交换使用的技术由发送线程确定。

同步交换技术提供了隐式形式的流控制，防止发送线程生成消息的速度快于接收线程消费消息的速度。
异步交换技术提供了显式形式的流控制，允许发送线程在发送后续消息之前确定先前发送的消息是否仍然存在。

实现
****

定义邮箱
========

邮箱使用 :c:struct:`k_mbox` 类型的变量进行定义。然后必须通过调用 :c:func:`k_mbox_init` 进行初始化。

以下代码定义并初始化一个空的邮箱。

.. code-block:: c

    struct k_mbox my_mailbox;

    k_mbox_init(&my_mailbox);

或者，可以通过调用 :c:macro:`K_MBOX_DEFINE` 在编译时定义和初始化邮箱。

以下代码与上面的代码段具有相同的效果。

.. code-block:: c

    K_MBOX_DEFINE(my_mailbox);

消息描述符
=========

消息描述符是 :c:struct:`k_mbox_msg` 类型的结构。只应使用下面列出的字段；
任何其他字段仅供邮箱内部使用。

*info*
    由消息发送者和接收者交换的 32 位值，其含义由应用程序定义。此交换是双向的，
    允许发送者在任何消息交换期间向接收者传递值，并允许接收者在同步消息交换期间向发送者传递值。

*size*
    消息数据大小，以字节为单位。在发送空消息或发送没有实际数据的消息缓冲区时，将其设置为零。
    在接收消息时，将其设置为所需的最大数据量，或者如果不需要消息数据，则设置为零。
    一旦收到消息，邮箱会用实际交换的数据字节数更新此字段。

*tx_data*
    指向发送线程的消息缓冲区的指针。在发送空消息时将其设置为 ``NULL``。接收消息时不要初始化此字段。

*tx_target_thread*
    所需接收线程的地址。将其设置为 :c:macro:`K_ANY` 以允许任何线程接收消息。
    接收消息时不要初始化此字段。一旦收到消息，邮箱会用实际接收者的地址更新此字段。

*rx_source_thread*
    所需发送线程的地址。将其设置为 :c:macro:`K_ANY` 以接收任何线程发送的消息。
    发送消息时不要初始化此字段。当消息放入邮箱时，邮箱会用实际发送者的地址更新此字段。

发送消息
========

线程首先创建其消息数据（如果有）来发送消息。

接下来，发送线程创建一个消息描述符，用于描述要发送的消息，如上一节所述。

最后，发送线程调用邮箱发送 API 以启动消息交换。如果当前存在兼容的接收线程，消息会立即给到该线程；
否则，消息会被添加到邮箱的发送队列。

任意数量的消息可以同时存在于发送队列中。发送队列中的消息根据发送线程的优先级进行排序。
优先级相等的消息会被排序，以便首先接收最旧的消息。

对于同步发送操作，操作通常在接收线程既接收了消息又检索了消息数据时完成。
如果在发送线程指定的等待时间到达之前未收到消息，则消息会从邮箱的发送队列中删除，发送操作失败。
当发送操作成功完成时，发送线程可以检查消息描述符以确定哪个线程接收了消息、交换了多少数据，
以及接收线程提供的应用程序定义的 info 值。

.. note::
   同步发送操作可能会无限期地阻塞发送线程，即使线程指定了最大等待时间也是如此。
   等待时间仅限制邮箱在消息被另一个线程接收之前等待的时间。一旦收到消息，
   接收线程检索消息数据和解除发送线程阻塞的时间*没有*限制。

对于异步发送操作，操作总是立即完成。这允许发送线程继续处理，无论消息是立即给到接收线程
还是添加到发送队列。发送线程可以可选地指定一个信号量 (semaphore)，当消息被邮箱删除时邮箱会给出该信号量，
例如，当消息已被接收线程接收并检索其数据时。使用信号量允许发送线程轻松实现流控制机制，
确保邮箱在任何时间点最多容纳来自发送线程（或发送线程集）的应用程序指定数量的消息。

.. note::
   异步发送消息的线程无法确定哪个线程接收了消息、交换了多少数据，或接收线程提供的应用程序定义的 info 值。

发送空消息
---------

此代码使用邮箱同步传递 4 字节随机值给任何想要的消费线程。消息"info"字段足够大，
可以承载正在交换的信息，因此不使用消息的数据部分。

.. code-block:: c

    void producer_thread(void)
    {
        struct k_mbox_msg send_msg;

        while (1) {

            /* 生成要发送的随机值 */
            uint32_t random_value = sys_rand32_get();

            /* 准备发送空消息 */
            send_msg.info = random_value;
            send_msg.size = 0;
            send_msg.tx_data = NULL;
            send_msg.tx_target_thread = K_ANY;

            /* 发送消息并等待消费者接收它 */
            k_mbox_put(&my_mailbox, &send_msg, K_FOREVER);
        }
    }

使用消息缓冲区发送数据
--------------------

此代码使用邮箱同步传递可变大小的请求从生产者线程到任何想要它的消费线程。
消息"info"字段用于交换有关每个线程可以处理的最大大小消息缓冲区的信息。

.. code-block:: c

    void producer_thread(void)
    {
        char buffer[100];
        int buffer_bytes_used;

        struct k_mbox_msg send_msg;

        while (1) {

            /* 生成要发送的数据 */
            ...
            buffer_bytes_used = ... ;
            memcpy(buffer, source, buffer_bytes_used);

            /* 准备发送消息 */
            send_msg.info = buffer_bytes_used;
            send_msg.size = buffer_bytes_used;
            send_msg.tx_data = buffer;
            send_msg.tx_target_thread = K_ANY;

            /* 发送消息并等待消费者接收它 */
            k_mbox_put(&my_mailbox, &send_msg, K_FOREVER);

            /* info、size 和 tx_target_thread 字段已更新 */

            /* 验证消息数据是否完全接收 */
            if (send_msg.size < buffer_bytes_used) {
                printf("some message data dropped during transfer!");
                printf("receiver only had room for %d bytes", send_msg.info);
            }
        }
    }

接收消息
========

线程首先创建一个消息描述符来接收消息，该描述符描述它想要接收的消息。然后它调用邮箱接收 API 之一。
邮箱搜索其发送队列并从找到的第一个兼容线程中获取消息。如果不存在兼容线程，接收线程可以选择等待。
如果在接收线程指定的等待时间到达之前没有出现兼容线程，则接收操作失败。一旦接收操作成功完成，
接收线程可以检查消息描述符以确定哪个线程发送了消息、交换了多少数据，以及发送线程提供的应用程序定义的 info 值。

任意数量的接收线程可以同时在邮箱的接收队列上等待。线程根据其优先级进行排序；
优先级相等的线程会被排序，以便首先开始等待的线程可以首先接收消息。

.. note::
    由于消息描述符指定的线程兼容性约束，接收线程并不总是按先进先出 (FIFO) 顺序接收消息。
    例如，如果线程 A 等待仅从线程 X 接收消息，然后线程 B 等待从线程 Y 接收消息，
    那么来自线程 Y 到任何线程的传入消息将被给到线程 B，线程 A 将继续等待。

接收线程控制从传入消息中检索的数据量以及数据最终到达的位置。线程可以选择获取消息中的所有数据、
仅获取数据的初始部分或完全不获取数据。同样，线程可以选择将数据复制到其选择的消息缓冲区。

以下各节概述了接收线程在检索消息数据时可以使用的各种方法。

在接收时检索数据
---------------

线程检索消息数据的最直接方法是在接收消息时指定消息缓冲区。线程指示消息缓冲区的位置
（不得为 ``NULL``）及其大小。

邮箱将消息的数据复制到消息缓冲区作为接收操作的一部分。如果消息缓冲区不够大以包含所有消息数据，
则任何未复制的数据都将丢失。如果消息不够大以用数据填充所有缓冲区，则消息缓冲区的未使用部分保持不变。
在所有情况下，邮箱都会更新接收线程的消息描述符以指示复制了多少数据字节（如果有）。

即时数据检索技术最适合在已知消息的最大大小的情况下的小消息。

以下代码使用邮箱使用即时数据检索技术处理来自任何生产线程的可变大小请求。
消息"info"字段用于交换有关每个线程可以处理的最大大小消息缓冲区的信息。

.. code-block:: c

    void consumer_thread(void)
    {
        struct k_mbox_msg recv_msg;
        char buffer[100];

        int i;
        int total;

        while (1) {
            /* 准备接收消息 */
            recv_msg.info = 100;
            recv_msg.size = 100;
            recv_msg.rx_source_thread = K_ANY;

            /* 获取数据项，根据需要等待 */
            k_mbox_get(&my_mailbox, &recv_msg, buffer, K_FOREVER);

            /* info、size 和 rx_source_thread 字段已更新 */

            /* 验证消息数据是否完全接收 */
            if (recv_msg.info != recv_msg.size) {
                printf("some message data dropped during transfer!");
                printf("sender tried to send %d bytes", recv_msg.info);
            }

            /* 计算所有消息字节的总和（0 到 100 个） */
            total = 0;
            for (i = 0; i < recv_msg.size; i++) {
                total += buffer[i];
            }
        }
    }

稍后使用消息缓冲区检索数据
------------------------

接收线程可以选择在接收消息时推迟消息数据检索，以便稍后可以将数据检索到消息缓冲区。
线程通过指定消息缓冲区位置为 ``NULL`` 和一个大小来指示它愿意稍后检索的最大数据量来实现此目的。

邮箱不会在接收操作的一部分中复制任何消息数据。但是，邮箱仍会更新接收线程的消息描述符
以指示有多少数据字节可供检索。

接收线程然后必须按如下方式响应：

* 如果消息描述符大小为零，则发送者的消息不包含数据，或者接收线程不想接收任何数据。
  接收线程不需要采取任何进一步的操作，因为邮箱已经完成了数据检索并删除了消息。

* 如果消息描述符大小不为零，并且接收线程仍想检索数据，线程必须调用 :c:func:`k_mbox_data_get`
  并提供一个足够大以容纳数据的消息缓冲区。邮箱将数据复制到消息缓冲区并删除消息。

* 如果消息描述符大小不为零，并且接收线程*不*想检索数据，线程必须调用 :c:func:`k_mbox_data_get`
  并指定消息缓冲区为 ``NULL``。邮箱删除消息而不复制数据。

后续数据检索技术适用于不希望立即检索消息数据的应用程序。例如，当内存限制使得接收线程
始终提供能够容纳最大可能传入消息的消息缓冲区不切实际时，可以使用它。

以下代码使用邮箱的延迟数据检索机制仅在消息满足某些条件时从生产线程获取消息数据，
从而消除不需要的数据复制。发送者提供的消息"info"字段用于对消息进行分类。

.. code-block:: c

    void consumer_thread(void)
    {
        struct k_mbox_msg recv_msg;
        char buffer[10000];

        while (1) {
            /* 准备接收消息 */
            recv_msg.size = 10000;
            recv_msg.rx_source_thread = K_ANY;

            /* 获取消息，但不获取其数据 */
            k_mbox_get(&my_mailbox, &recv_msg, NULL, K_FOREVER);

            /* 仅为某些类型的消息获取消息数据 */
            if (is_message_type_ok(recv_msg.info)) {
                /* 检索消息数据并删除消息 */
                k_mbox_data_get(&recv_msg, buffer);

                /* 处理"buffer"中的数据 */
                ...
            } else {
                /* 忽略消息数据并删除消息 */
                k_mbox_data_get(&recv_msg, NULL);
            }
        }
    }
