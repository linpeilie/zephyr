平衡红黑树
==========

对于排序容器在运行时可能变大的情况,列表由于搜索它的算法成本而成问题。对于
这些情况,Zephyr 提供了一个平衡树实现,它在搜索和删除操作上的运行时间在大小
为 N 的树中以 O(log2(N)) 为界。这是使用多个学术来源描述的传统红黑树实现的。

rbtree 的 :c:struct:`rbtree` 跟踪结构可以在用户可访问内存中的任何位置初始化。
在首次使用之前,它应该只包含零位。不需要或不需要特定的初始化 API。

与列表不同,其中位置是显式的,rbtree 中节点的排序必须由用户作为谓词函数提供。
应在尝试任何树操作之前将 :c:func:`rb_lessthan_t` 类型的函数分配给
:c:struct:`rbtree` 结构的 ``lessthan_fn`` 字段。如其名称所示,如果第一个
节点参数在树所需的排序中"小于"第二个节点参数,则此函数应返回布尔 True 值。
请注意,不允许"相等",树中的节点必须具有单一固定顺序才能使算法正确工作。

与 slist 和 dlist 容器一样,rbtree 中的节点表示为 :c:struct:`rbnode` 结构,
该结构存在于用户管理的内存中,通常嵌入在树中跟踪的数据结构中。与列表代码
不同,rbnode 中的数据完全不透明。用户无法提取二叉树拓扑并像列表那样"手动"
遍历树。

可以使用 :c:func:`rb_insert` 将节点插入树中,使用 :c:func:`rb_remove`
删除。通过 :c:func:`rb_get_min` 和 :c:func:`rb_get_max` 提供对树中"第一个"
和"最后一个"节点(在比较函数定义的顺序意义上)的访问。还有一个谓词
:c:func:`rb_contains`,如果提供的节点指针作为树中的元素存在,则返回布尔
True。如上所述,所有这些例程都保证在树的大小中最多具有对数时间复杂度。

提供了两种机制来枚举 rbtree 中的所有元素。第一个 :c:func:`rb_walk` 是一个
简单的回调实现,其中调用者指定 C 函数指针和要传递给它的无类型参数,树代码
按顺序为每个节点调用该函数。这具有非常简单的实现的优点,但代价是用户的 API
有些麻烦(与 ISO C 的 :c:func:`bsearch` 例程不同)。但是,它是递归实现,
因此在禁止使用无界栈技术(如递归)的环境中并不总是可用。

还提供了 :c:macro:`RB_FOR_EACH` 迭代器,它与列表的类似 API 一样,使用嵌套
代码块而不是回调,以更自然的方式迭代列表。它也是非递归的,尽管默认情况下
它需要栈上的对数大小空间(但是,可以配置为使用固定/最大大小缓冲区,以避免
动态分配)。与列表一样,这也在 :c:macro:`RB_FOR_EACH_CONTAINER` 变体中
可用,该变体使用指向容器字段的指针而不是原始节点指针进行枚举。

树内部
------

如所述,Zephyr rbtree 实现是学术来源中普遍描述的传统红黑树。有关算法的
低级详细信息超出了本文档的范围,因为它们符合现有约定。此讨论将限于 Zephyr
实现的值得注意或特定的细节。

树保证的核心不变量是,从树的根到任何叶的路径不超过到任何其他叶的路径的两倍。
这是通过将一位"颜色"与每个节点(红色或黑色)相关联并强制执行规则来实现的,
即红色子节点不能是另一个红色子节点的子节点(即任何路径到根的黑色节点数必须
相同,并且不能超过该数量的"额外"红色节点)。此规则由一组旋转规则强制执行,
这些规则用于在修改后"修复"树。

.. figure:: rbtree.png
    :align: center
    :alt: rbtree 示例
    :figclass: align-center

    黑色高度为 2 的最大不平衡 rbtree。在不重新平衡的情况下,不能在最右边的
    节点下方添加更多节点。

这些旋转在概念上实现在原语之上,该原语"交换"列表中一个节点与另一个节点的
位置。典型的实现通过简单地交换节点内部"数据"指针来实现这一点,但因为
Zephyr :c:struct:`rbnode` 是侵入式的,所以这不起作用。Zephyr 必须包含更
精细的代码来处理边缘情况(例如,一个交换的节点可以是根,或者两个可能已经是
父/子)。

Zephyr rbtree 的 :c:struct:`rbnode` 结构仅包含两个指针,表示二叉树中节点的
"左"和"右"子节点。但是,在修改后为重新平衡而遍历树通常需要能够从节点"向上"
迭代。在行业中,红黑树为此目的存储第三个"父"指针是非常常见的。Zephyr 通过
在向下遍历树时本地构建节点指针的"栈"并在进行修改时适当地更新它来避免此
要求。因此,Zephyr rbtree 可以实现为每个节点不超过 dlist 的运行时存储开销。

这些属性,即平衡树数据结构,每个节点仅使用两个数据指针,并且无需任何内存
分配 API 即可工作,在行业中非常罕见,并且在某种程度上是 Zephyr 独有的。
