平衡红黑树 (Balanced Red/Black Tree)
=====================================

对于排序容器在运行时可能变得很大的情况，由于搜索它的算法成本，列表会成为问题。
对于这些情况，Zephyr 提供了一个平衡树实现，它对大小为 N 的树的搜索和删除操作
的运行时间限制为 O(log2(N))。这是使用多个学术来源描述的传统红黑树实现的。

rbtree 的 :c:struct:`rbtree` 跟踪结构可以在用户可访问的内存中的任何位置初始化。
在首次使用之前，它应该只包含零位。不需要或不需要特定的初始化 API。

与列表不同，位置是显式的，rbtree 中节点的排序必须由用户作为谓词函数提供。
类型为 :c:func:`rb_lessthan_t` 的函数应在尝试任何树操作之前分配给
:c:struct:`rbtree` 结构的 ``lessthan_fn`` 字段。如其名称所示，
如果第一个节点参数在树所需的排序中"小于"第二个节点参数，则此函数应返回布尔 True 值。
请注意，不允许"相等"，树中的节点必须具有单一固定的顺序才能使算法正常工作。

与 slist 和 dlist 容器一样，rbtree 中的节点表示为 :c:struct:`rbnode` 结构，
该结构存在于用户管理的内存中，通常嵌入在树中跟踪的数据结构中。
与列表代码不同，rbnode 中的数据完全不透明。用户无法提取二叉树拓扑并"手动"遍历树，
就像列表那样。

可以使用 :c:func:`rb_insert` 将节点插入树中，并使用 :c:func:`rb_remove` 删除。
通过 :c:func:`rb_get_min` 和 :c:func:`rb_get_max` 提供对树中"第一个"和"最后一个"节点
（在比较函数定义的顺序意义上）的访问。还有一个谓词 :c:func:`rb_contains`，
如果提供的节点指针作为元素存在于树中，则返回布尔 True。
如上所述，所有这些例程都保证最多具有树大小的对数时间复杂度。

提供了两种机制来枚举 rbtree 中的所有元素。第一种是 :c:func:`rb_walk`，
这是一个简单的回调实现，其中调用者指定一个 C 函数指针和一个要传递给它的无类型参数，
树代码为每个节点按顺序调用该函数。这具有非常简单的实现的优点，
代价是对用户来说有点笨拙的 API（与 ISO C 的 :c:func:`bsearch` 例程不同）。
但是，它是一个递归实现，因此在禁止使用无界堆栈技术（如递归）的环境中并不总是可用。

还提供了一个 :c:macro:`RB_FOR_EACH` 迭代器，它与列表的类似 API 一样，
以更自然的方式遍历列表，使用嵌套代码块而不是回调。它也是非递归的，
尽管它默认情况下需要堆栈上的对数大小空间（但是，这可以配置为使用固定/最大大小缓冲区，
以避免动态分配）。与列表一样，这也可以在 :c:macro:`RB_FOR_EACH_CONTAINER`
变体中使用，该变体使用指向容器字段的指针而不是原始节点指针进行枚举。

树内部 (Tree Internals)
------------------------

如所述，Zephyr rbtree 实现是在学术来源中普遍描述的传统红黑树。
有关算法的低级详细信息超出了本文档的范围，因为它们符合现有约定。
本讨论将限于 Zephyr 实现特有或特定的详细信息。

树保证的核心不变量是从树根到任何叶子的路径不超过到任何其他叶子的路径的两倍长。
这是通过将一位"颜色"（红色或黑色）与每个节点关联并强制执行一条规则来实现的，
即没有红色子节点可以是另一个红色子节点的子节点（即，到根的任何路径上的黑色节点数量
必须相同，并且不能存在超过该数量的"额外"红色节点）。
此规则由一组旋转规则强制执行，用于在修改后"修复"树。

.. figure:: rbtree.png
    :align: center
    :alt: rbtree 示例
    :figclass: align-center

    黑色高度为 2 的最大不平衡 rbtree。在不重新平衡的情况下，
    不能在最右边的节点下添加更多节点。

这些旋转在概念上是在一个原语之上实现的，该原语"交换"一个节点与列表中另一个节点的位置。
典型的实现只是通过交换节点的内部"数据"指针来实现这一点，
但由于 Zephyr :c:struct:`rbnode` 是侵入式的，因此无法工作。
Zephyr 必须包含更复杂的代码来处理边缘情况（例如，一个交换的节点可以是根，
或者两个节点可能已经是父/子关系）。

Zephyr rbtree 的 :c:struct:`rbnode` 结构仅包含两个指针，
表示二叉树中节点的"左"和"右"子节点。但是，在修改后为重新平衡而遍历树时，
通常需要能够从节点向"上"迭代。业界的红黑树为此目的存储第三个"父"指针是非常常见的。
Zephyr 通过在向下遍历树时本地构建节点指针的"堆栈"并在进行修改时适当更新它来避免此要求。
因此，Zephyr rbtree 可以实现，每个节点的运行时存储开销不超过 dlist。

这些属性，即一个平衡树数据结构，每个节点只需要两个指针数据并且无需任何内存分配 API，
在业界非常罕见，并且是 Zephyr 独有的。
